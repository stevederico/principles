# Value: feedback

**Rule:** Honor every iteration commitment with working software, demo early and often, listen, change what is needed, and adapt the process to the project.

**Why:** Feedback arrives at many levels: developers by pairing and testing as they write, managers at the stand-up, customers via acceptance scores and demos each iteration. Changes in requirements are part of feedback and gladly accepted.

**Do:**
```
each iteration: deliver working software and demo it
listen; apply the changes needed
adapt the process to the project, not the project to the process
```

**Don't:** Bending the project to fit the process.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/values.html, http://www.extremeprogramming.org/introduction.html, http://www.extremeprogramming.org/index.txt
