# Own your test framework

**Rule:** Treat the unit test framework as a development tool used all project long, and make it the team's own by learning it and changing any part.

**Why:** It is not only a testing tool: it helps formalize requirements, clarify architecture, write and debug code, integrate, release and optimize. Building a simple one is not hard, and understanding it lets you tailor it, which can save large amounts of time. Start from a free version, refactor it, and make it yours.

**Do:**
```
download a free framework for your language
read it, refactor it, extend it for team needs
use it from day one, not only at the end
```

**Don't:** Keeping the framework in reserve until the last month, or treating it as someone else's code.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/rules/unittestframework.html, http://www.extremeprogramming.org/example/utframe.html, http://www.extremeprogramming.org/example/utframesource.html
