# Move people around

**Rule:** Encourage everyone to work on a new part of the system for part of each iteration, using pair swaps to move people.

**Why:** Moving people avoids knowledge loss and coding bottlenecks when one person owns an area. Together with pairing it cross-trains the team, so anyone can work on the hottest part and load balances freely. A pair can swap one person out while the other stays for continuity.

**Do:**
```
each iteration: everyone tries a section they have not worked on
swap one half of a pair; the other half carries the context
```

**Don't:** Letting one person be the only one who knows an area.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/rules/movepeople.html
