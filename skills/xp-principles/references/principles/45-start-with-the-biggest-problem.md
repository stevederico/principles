# Start with the biggest problem

**Rule:** Begin XP on a new project with stories and risk spikes, or on a troubled one by adding the practice that fixes your biggest problem first.

**Why:** A new project spends only a few weeks on stories and spikes, then holds release planning with customers, developers and managers, then starts iterations. For troubled projects: useless specs lead to stories; shifting requirements to lighter release planning and iterations; production bugs to automated acceptance tests; integration bugs to unit tests at 100 percent; bottleneck owners to collective ownership. The middle of adoption is a climb, especially pairing; keep going.

**Do:**
```
new project: stories + spikes (weeks) -> release planning -> iteration 1
troubled project: list the worst problem; add the XP practice aimed at it
repeat until no problems left; then add the rest
```

**Don't:** Going back to the familiar method when adoption gets hard.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/start.html
