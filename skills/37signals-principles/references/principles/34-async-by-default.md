# Collaborate in writing by default, on a fixed rhythm

**Rule:** First choice is to post a message, document or request with context and a needed-by date and expect an eventual answer; use real time only when async is inefficient. Make work visible through short recurring written updates.

**Why:** Reading on one's own schedule avoids breaking people's flow. Distributed teams cannot rely on overhearing, and regular updates build trust in where the team is going and why. Comparing a cycle's completed summary with its kickoff plan closes the loop.

**Do:**
```
need = write(context, question, needed_by) ; post ; wait
escalate to a call only if blocked or the topic is tight and iterative
daily: what I did and why ; weekly: what I will do ; per cycle: plan, then completed work
```

**Don't:** Treat a chat message as a demand for immediate reply, or replace written updates with ad hoc interrupts.

**Break it when:** An incident, or tight pairing.

**Source:** https://github.com/basecamp/handbook/blob/main/how-we-work.md (Communication, Asynchronously) ; https://basecamp.com/shapeup/1.5-chapter-06. Docs only.
