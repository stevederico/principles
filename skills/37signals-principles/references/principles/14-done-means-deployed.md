# Done means deployed inside the time box

**Rule:** Count work as finished only when it is tested and deployed within the committed window; push low-variance extras (help text, announcements) after.

**Why:** A budget means nothing if work can finish "later", so testing must be inside it. Documentation and announcements rarely take many times longer than planned, so they can wait without risking the date.

**Do:**
```
scope the essential parts -> finish early -> test within the cycle -> deploy
defer: docs, marketing, announcements
for a brand-new product in production mode: "shipped" = merged to main and left alone
```

**Don't:** Call "code complete" done and leave QA and release to a hazy later.

**Break it when:** You are not shipping to customers yet; then the merge is the finish line.
