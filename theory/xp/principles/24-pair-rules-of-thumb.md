# Rules of thumb for pairing

**Rule:** Follow five rules: never pair two newcomers, both must see the screen, split work is not pairing, nobody works alone, and give trust time to grow.

**Why:** These came from the VCAPS project and match what people learn after pairing badly and then well. Pairs who divide the work, even with shared responsibility, are not pair programming.

**Do:**
```
new pair? one old-timer + one newcomer
both people can see the monitor, always
no splitting up while calling it a pair
no lone rangers: everyone works in a pair
```

**Don't:** Splitting work between partners yet calling it pairing.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/stories/pair2.html
