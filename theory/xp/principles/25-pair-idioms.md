# Pair idioms

**Rule:** Use named moves to keep a pair productive: be honest, try the partner's idea first, drop both ideas for a third, test with a tiny experiment, and stop a failing patch.

**Why:** Honesty matters: a partner who cannot say the code is bad loses the benefit. Other moves: switch explanation mode when not understood; settle a standoff with an experiment, not a brick; abandon an almost-working attempt and restart; leave small typing errors to the driver; slow down if your partner is lost; split tests and code between you if one drifts; remind each other of the rules.

**Do:**
```
stuck arguing:        try partner's idea first
still stuck:          throw both away, find a third
"I know it is false": write the simplest experiment
attention drifting:   ping-pong (one writes test, the other code)
going too fast:       slow down, use the mouse, keep partner in the loop
```

**Don't:** Backseat driving over small mistakes, or racing ahead while your partner is lost.

**Break it when:** The site names no exception.
