# Small frequent releases

**Rule:** Release working, tested software to the customer at the end of every iteration, in production every week or two at least, with the customer deciding when to go live.

**Why:** Early use of small business-sized pieces gives feedback while it can still change the system. The longer an important feature waits, the less time is left to fix it. Delivering partial systems early also exposes big changes before they get expensive.

**Do:**
```
each iteration end:
    build is tested, integrated, production ready
    demo it to the customer
    customer decides whether it goes to production
```

**Don't:** Holding back an important feature from the users until late in the project.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/rules/releaseoften.html, http://www.extremeprogramming.org/change.html, http://www.extremeprogramming.org/introduction.html
