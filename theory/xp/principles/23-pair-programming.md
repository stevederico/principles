# Pair-program all production code

**Rule:** Write all code that goes to production in pairs, two people at one computer, sharing keyboard and mouse and both watching the code.

**Why:** A pair adds as much functionality as two working apart, with higher quality and big savings later. In a Utah experiment with 42 seniors, pairs used 60 percent more programmer hours on the first task, 20 percent on the second and 10 percent on the third, passed about 15 percent more tests, and over 90 percent enjoyed it more. It is a social skill that takes time, and it is not mentoring: equals give and take, whatever their rank.

**Do:**
```
sit side by side; slide keyboard and mouse back and forth
both attend to the code being written
say "let's try your idea first" when it helps
expect awkwardness at first; get an experienced pair to show the feel
```

**Don't:** Treating it as a teacher-student session, or expecting people to be good at it from the start.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/rules/pair.html, http://www.extremeprogramming.org/stories/pair6.html
