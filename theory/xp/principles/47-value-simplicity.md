# Value: simplicity

**Rule:** Do what is needed and asked for, but no more, in small steps toward the goal.

**Why:** This maximizes value for the investment so far, mitigates failures as they occur, and yields something the team is proud of and can keep for reasonable cost. The site says to keep designs simple and clean.

**Do:**
```
before work: is this needed and asked for? if not, drop it
take the smaller step; fix failures as they appear
```

**Don't:** Building extra because it might be useful.

**Break it when:** The site names no exception.

**Source:** http://www.extremeprogramming.org/values.html, http://www.extremeprogramming.org/index.txt
