# Pairing replaces reviews and egos

**Rule:** Skip formal code reviews in favor of pairing, and take pride in the team's code instead of your own.

**Why:** A formal review feels like personal criticism, and one developer lost her enthusiasm after two. Pairing swaps criticism and competition for learning and cooperation: partners explain, one teaches, roles reverse, and the code passes two pairs of eyes. Egoless programming never works; pride in good code is natural, so spread it across everyone's work.

**Do:**
```
code in pairs, so review happens while writing
explain your thinking to your partner; swap roles
praise good code regardless of who wrote it
```

**Don't:** Formal group reviews with a lone, often inexperienced, author.

**Break it when:** The site names no exception.
